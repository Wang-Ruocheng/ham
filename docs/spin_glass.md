# EA 自旋玻璃：独立的平行回火数据流程

此流程生成有限周期晶格上的 Edwards–Anderson（EA）自旋玻璃数据，保留无序样本、温度、真实副本、采样时刻、空间轴及键的身份。入口是 `python -m scripts.generate_spin_glass`，数据 API 位于 `recurrent_rg/data/spin_glass_pipeline.py`。

数据生成与读取的空间维数支持 `1 <= D <= 16`，包括长方体形状；当前 QCR 模型与训练流程仍只支持一维和二维。生成三维数据不等于已有三维 Q、C、R、粗粒化或训练适配，也不能直接把新数据目录传给历史训练器。数据示例用于审查计划；一维和二维重叠场学习适配见下文，采样本身不构成平衡认证。

## 物理约定与副本身份

自旋 `s_x ∈ {-1,+1}`，取 `k_B=1`，使用

\[
H(s;J,h)=-\sum_{x,a}J_{a,x}s_xs_{x+e_a}-h\sum_xs_x.
\]

每个空间轴使用周期边界。`bonds[a, x]` 是从 `x` 指向 `x+e_a` 的一条正向键，哈密顿量中的每条键只计一次。所有轴长必须至少为 3，避免长度为 1 或 2 时的自环及周期多重边约定歧义。

每个 `disorder_id` 独立生成一套 quenched（淬火）随机键 `J`，并在该无序样本的整次热采样中固定。支持两种键分布：

- `bimodal`：`J=+bond_scale` 的概率为 `positive_probability`，否则 `J=-bond_scale`。`bond_scale>0`、`0<positive_probability<1`；此分布的 `bond_mean` 必须为 0。数据流程拒绝必然生成相同键的退化 `p=0/1`；低层物理函数可另行用于这些极限的单元测试。
- `gaussian`：`J=bond_mean+bond_scale*N(0,1)`，其中 `bond_scale>0` 是标准差；此分布的 `positive_probability` 必须保留默认值 0.5。

温度与 `J` 采用同一能量单位；它们是采样和事后评价元数据，不是 QCR 的训练监督标签。

`replicas` 表示同一 `J` 下的真实热副本数量。每个真实副本都有一整条独立的平行回火（PT）温度梯度，各梯度共享 `J`，但不在真实副本之间交换构型。温度槽位也不是“真实副本”：一个 PT 梯度中的构型会随交换在温度间移动，而真实副本身份始终不变。

在同一无序、温度及保存时刻，对两个不同真实副本定义

\[
q_x^{ab}=s_x^{(a)}s_x^{(b)},\qquad
q^{ab}=\frac1N\sum_x q_x^{ab}.
\]

不能把同一 PT 梯度的两个不同温度槽位当作同温独立副本来计算这个重叠量。多个副本对共享真实副本时，各对的统计量也不相互独立。

## 采样规则与诊断边界

采样结合固定 lazy Metropolis 局域更新及同一真实副本内的相邻温度交换。每轮随机排列所有格点，逐点访问一次；每次访问独立以 1/2 概率提议翻转，否则原地停留，翻转提议再按 Metropolis 概率接受。这个固定停留机制避免零键等特殊情形下每轮全翻转的周期性。温度梯度至少含两个严格递增的有限正温度。`T=0` 被拒绝；该流程不提供基态求解，也不会用低温有限链样本冒充基态。

令 `beta_i=1/T_i`，相邻槽位当前能量为 `E_i,E_j`，构型交换的接受概率为

\[
\min\{1,\exp[(\beta_i-\beta_j)(E_i-E_j)]\}.
\]

这个交换保持固定 `J` 下的多温度乘积分布。挫折及负键使铁磁模型的普通 Wolff 成簇规则不能直接复用。

`burn_in`、`spacing`、`exchange_interval` 和 `seed` 在开始前固定。保存前执行 `burn_in` 轮；随后每 `spacing` 轮保存一组构型，共 `samples` 组，因此每个温度、每个真实副本的计划轮数为 `burn_in + samples*spacing`。`site_visits` 记录所有格点访问，`local_attempts` 只计实际翻转提议，`local_accepts` 计接受的翻转；三者不能混用为接受率分母。交换按 `exchange_interval` 调度。记录的构型属于相关 MCMC 数据，不假定独立同分布。

数据流程采用预先固定的 mixed 初态：偶数编号真实副本从随机自旋开始，奇数编号从全 `+1` 开始。局域及交换计数包括 burn-in；温度访问计数包括初始位置及每轮结束时的位置。往返按每个构型 walker 统计“首次到达的端点→另一端点→原端点”的完整旅程，尚未到达任一端点的中间 walker 没有往返起点。初态与这些计数的定义都不构成平衡证据。

每个无序样本的诊断包括能量密度、磁化、`q`、`q²`、`q⁴`、重叠相关、局域更新及温度交换计数、温度访问和往返计数，并给出保存序列的 lag-1 相关与近似 ESS。输出中的

\[
\chi_{\mathrm{SG,raw}}=N\langle q^2\rangle
\]

是单个无序样本内的未连通重叠 susceptibility 估计；尤其在 `h!=0` 时，不能称为连通自旋玻璃 susceptibility。无序平均先在每个固定 `J` 内做热平均及副本对平均，再对不同 `J` 等权平均。

ESS 和积分自相关时间是有限保存序列上的描述性估计；常量或过短序列会给出不可辨识标记，而不是把“没有变化”解释为充分采样。低交换接受率、零完整往返、短序列或不同观测量的混合困难应按诊断原样报告。较好的接受率、往返或 ESS 也不能证明已达平衡、已充分遍历态空间或已恢复热力学极限。

流程不会根据诊断自动加样、重置种子、延长链、拟合临界点或启动训练。输出状态 `complete` 只表示请求的数据工作流完成，不表示平衡认证。

## 先审查小规模计划

下面只做一个 `3x3x3`、3 套无序、2 个真实副本、3 个温度的小计划检查。`--dry-run` 验证参数、划分及预算后打印 JSON；不采样、不创建输出目录、不写文件。

```bash
python -m scripts.generate_spin_glass \
  --output data_cache/ea3d_plan_seed91 \
  --dimension 3 --length 3 \
  --temperatures 0.5 1.0 2.0 \
  --disorders 3 --replicas 2 --samples 4 \
  --burn-in 8 --spacing 2 --exchange-interval 1 \
  --distribution bimodal --bond-scale 1 \
  --positive-probability 0.5 --field 0 --seed 91 \
  --test-every 3 --test-offset 1 \
  --max-spin-proposals 50000000 --max-output-gib 2 --max-memory-gib 0.5 \
  --max-sites 1000000 --dry-run
```

这个计划共有 7,776 次格点访问，也是实际单自旋翻转提议数的保守上界，适合检查轴、预算及划分含义；其链长不构成可用于物理结论的采样方案。长方体可以把 `--dimension 3 --length 3` 替换为 `--shape 3 4 5`；维数由轴数推断，也可显式给出匹配的 `--dimension 3`。`--shape` 与 `--length` 互斥；省略两者时默认每轴长度 9，未给维数则默认二维。

至少需要 3 套无序、2 个真实副本和每温度每副本 4 个保存样本。`burn_in` 可为 0，`spacing` 及 `exchange_interval` 至少为 1。没有给出温度梯度时命令会拒绝执行。

生成器在分配和采样前检查格点数、工作量、预计输出和预计内存。格点访问次数（用作单自旋提议数预算的保守上界）为

\[
N_{\mathrm{disorder}}N_{\mathrm{replica}}N_T
\left(\prod_a L_a\right)
(\mathrm{burn\_in}+\mathrm{samples}\,\mathrm{spacing}).
\]

默认上限分别为 1,000,000 个格点、50,000,000 次格点访问、2 GiB 输出及 0.5 GiB 预计内存。字节数与工作量都是保守投影，不是实际进程 RSS、运行耗时或文件大小的实测保证；维数增加会使格点数、键和数据量迅速增长。当前实现是 CPU 串行流程，未使用 GPU 或分布式调度。

正式调用需显式去掉 `--dry-run`，并使用尚不存在的输出目录。已有目录会被拒绝，流程不覆盖、不续写已有数据。失败时保留已产生的文件及失败状态供检查，读取器拒绝把不完整目录作为完整数据集加载。

## 文件格式与完整性

新数据使用独立 schema `edwards_anderson_pt_v1`，不伪装成历史 `EnsembleDataset` 缓存。

```text
数据目录/
  plan.json
  status.json
  manifest.json
  sampling.json
  shards/
    disorder_000000.npz
    disorder_000001.npz
    ...
```

`plan.json` 保存输入、物理约定、轴约定、预算投影和预定划分。`status.json` 记录执行完成或失败状态。`manifest.json` 保存每个分片的无序 ID、划分、文件大小、SHA-256、键种子及热采样种子，并记录计划、诊断和采样代码的指纹。`sampling.json` 保存逐无序诊断与等权无序平均。主种子以固定规则派生各无序的键种子及热采样种子；完整复现仍需同时保留参数、代码和实际数据指纹。

每个分片对应一套固定 `J`，包含它的所有温度与真实副本：

| 数组 | 形状或含义 |
| --- | --- |
| `bonds` | `[D, *shape]`，正向周期键 |
| `configurations` | `[T, R, S, *shape]`，`int8`，值为 `-1/+1` |
| `energies` | `[T, R, S]`，完整哈密顿量能量 |
| `temperatures` | `[T]`，严格正且递增 |
| `disorder_id`、`bond_seed`、`sampling_seed` | 无序与随机数身份 |
| `swap_attempts`、`swap_accepts` | 各真实副本的相邻温度交换计数 |
| `local_attempts`、`local_accepts` | 局域 Metropolis 更新计数 |
| `site_visits` | 包括原地停留的所有格点访问计数 |
| `round_trips`、`temperature_visits` | 梯度内构型的温度旅行诊断 |

这里表头中的 `T/R/S` 分别是温度数量、真实副本数量和保存样本数量，不额外引入训练特征轴。

## 按整套无序划分并读取

留出单位是整个 `disorder_id`。规则为 `disorder_id % test_every == test_offset` 时进入 `test`，其余进入 `train`。默认 `test_every=3,test_offset=1`，上面 3 套无序的例子得到训练 ID `0,2` 和测试 ID `1`。每套无序的所有温度、真实副本及保存时刻始终处于同一划分；不能先展开这些轴再随机拆分。此外，流程检查实际键数组的 SHA-256：若两个不同 ID 偶然生成完全相同的键且位于不同划分，会保留现场并拒绝继续，不自动重采或换种子。有限小晶格的双峰分布尤其可能遇到重复；同一划分内的重复在 manifest 的独特键数量中据实反映。参数验证也要求最终训练及测试都非空，读取器在返回任何数据前再次检查跨集键指纹。

```python
from recurrent_rg.data.spin_glass_pipeline import iter_spin_glass

# 路径应指向另外明确生成并完成的数据集；dry-run 示例不会产生该目录。
for record in iter_spin_glass("data_cache/ea_completed", split="train"):
    spins = record.spin_view(replica=0)       # [T, S, *shape, 1]
    overlap = record.overlap(a=0, b=1)       # [T, S, *shape]
    overlap_input = record.overlap_view()    # [T, S, *shape, 1]
    # record.split 保留整套无序的划分，T/J 仍留在记录的元数据中。
```

`iter_spin_glass(output, split=None, verify_hashes=True)` 逐分片返回 `SpinGlassRecord`。默认校验完整状态、manifest/计划/诊断/分片指纹、分片大小、形状、温度及无序身份，并核对保存能量与自旋、键和场的一致性。`split=None` 会遍历全部记录；训练和测试应分别使用显式 `split`，并继续保留记录中的身份。

`spin_view` 和 `overlap_view` 只返回自旋或重叠场，不拼入温度、键、无序 ID 或能量。温度轴仍用于索引不同系综，不是温度数值通道。返回这样的视图不代表已实现训练适配：单自旋输入与重叠输入是不同建模选择，接入 QCR 还需要明确表示、粗粒化以及按无序的批处理设计。

后续若开展一维或二维 QCR 实验，应继续遵守仓库 `AGENTS.md` 的当前固定配方；二维使用非重叠 `3x3`、stride 3 的随机可训练概率 C，并按请求的粗粒化层数选择可整除的尺寸。不要通过 legacy 开关绕过训练约定。温度与耦合标签只用于采样、评价和绘图，不进入 QCR loss；应报告 `R(g)`（箭头使用 `R(g)-g`）、耦合到 `g` 的映射及损失曲线，新图中文字使用中文。数据生成入口本身不启动训练。

## 一维重叠场的无监督 QCR 学习

`scripts.prepare_spin_glass_qcr` 将完整的一维或二维数据转换为历史训练器能够验证的系综缓存。输入是同一 `J`、同温度、同一保存时刻的两个独立真实副本之积 `q_x=s_x^0*s_x^1`，不是单自旋磁化。每个 `(disorder_id, temperature_index)` 对应一个系综；整套 `J` 仍只属于一个 split。缓存的 `couplings=None`，温度、键指纹及一维环通量只写入 `evaluation_metadata.json`，不拼入模型输入或损失。二维记录局域受挫方格的比例，不使用一维 `ring_flux` 分组；三维数据会被这个 QCR 适配器拒绝。

`configs/spin_glass1d_overlap_g1_seed91.json` 使用空间一维、`theory_dim=1`、非重叠两点随机可训练概率 C、共享仿射局域分布重构 Q，以及独立梯度的 Q/C/R 默认配方；单步和多步闭合各自对目标尺度等权。Q、C、R 从随机初始化同时训练，Adam 学习率 0.001、6000 次更新，不使用 K/T 监督、额外 future loss、预训练或固定核。

`scripts.run_spin_glass1d` 是单次、新目录、冻结代码的顺序入口：采样 → 重叠缓存 → 默认训练器 → 中文报告。正式配置为 `L=128`、9 套独立等概率 `±1` 键（6 TRAIN/3 TEST）、每套两个真实热副本、10 个温度 `[.25,.35,.45,.6,.8,1.,1.3,1.7,2.2,3.]`、1024 轮预热、间隔 8 轮保存 64 个构型；共 35,389,440 次格点访问，学习尺度为 `128→64→32→16`。采样和优化种子分别为 20261019、91。正式设备固定为 225 上的 `cuda:2`，每个 GPU 阶段前重复检查空闲、内存、负载和 I/O；单 CPU 线程，父进程只施加一次 nice 10。

运行器的 GPU 阶段墙时、CPU 核秒和目录大小为阶段前后门控，并非强杀式硬时限。训练器另有 600 秒更新循环限额；不足 6000 步时标为 `budget_hold`，不自动续训、换种子或减小实验。`--execution-smoke` 仅进行独立小型两步执行检查，不能作科学结果。正式运行后不修改冻结代码或覆盖其根目录。

`scripts.report_spin_glass1d` 只评价已保存模型，不更新参数；校验缓存、配置及模型前后指纹，保存无梯度回执。报告分别给出逐 C draw 和先平均 C 的闭合 RMSE、使用 TRAIN 目标总体标准差的 NRMSE、按独立无序及环通量分组的结果、同 C 轨迹的 half-Q/full-Q 差异、`R(mean g)` 与 `mean R(g)`，以及四张中文图。公开 `encodings.npz` 不含原始自旋、键或模型参数。温度和 C 重复均不是额外独立无序样本。

一维零场 `±J` 链的局域键符号可规范消去，周期边界只保留环通量的区别；所以这是受控的一维重叠场学习验证，不是高维复杂玻璃相的证明。临界点在 `T=0`，本流程仅含有限正温度，不搜索有限温度相变点或拟合热临界指数。有限长度和相关 MCMC 的限制始终保留。

## 二维重叠场的无监督标量实验

`configs/spin_glass2d_overlap_g1_seed91.json` 与 `scripts.run_spin_glass2d` 是独立于一维结果的新入口。默认使用二维非重叠 `3×3`、stride 3 的随机可训练概率 C，`d_g=1`，`36×36→12×12→4×4`，Q/C/R 默认目标与独立梯度、均匀目标尺度权重、Adam 0.001 和固定 6000 次更新。没有温度、键、理论临界点或指数监督，没有 future/response 额外目标，不沿用一维 b2。

预先固定的采样方案为：9 套等概率 `±1` 随机键（6 TRAIN/3 TEST）、零场、每套两条独立真实副本 PT 梯度；20 个几何间隔温度 `0.5*7**(i/19), i=0..19`；预热 2048 轮、间隔 16 轮保存 64 个构型。总计 1,433,272,320 次格点访问，显式计数上限为 1,500,000,000。正式启动前只检查固定计划，不根据 ESS 或流场结果自动增加工作量。小型执行检查使用 `12×12→4×4`、两次更新，不是科学结果。

二维模型有不能通过规范变换消去的局域受挫，适配侧车保存方格四条键符号积为负的比例（及零积比例）；这些评价元数据不进入训练缓存。`scripts.report_spin_glass2d` 对已保存模型进行冻结评价，使用二维 16-bin 方格重构目标，不误用一维二点目标。公开闭合双口径、TRAIN 标准差归一化、half/full-Q、真实 `R(g)-g`、温度到 g、损失和轨迹图，以及前后模型指纹不变回执。

该二维零场对称 ±J 模型的理论临界点位于 `T=0`，但本轮只含有限正温、少量无序和单一微观尺寸。PT 交换率、往返和 ESS 只能描述有限采样，不能认证热化、基态或临界行为。无序重整化本来是耦合分布的流，标量 `g` 不一定全局闭合；多出的吸引/排斥交点也可能来自投影、有限尺寸、未热化或 R 外插。报告不搜索根、不估计临界温度或指数，也不将二维流场与一维坐标直接混比。

## 独立的 Houdayer 采样对照试验

`scripts.run_spin_glass_sampling_trial` 只比较采样，不启动 QCR、模型推理或指数拟合。它保持原二维零场 `±J` 的 `36×36`、20 个温度及既有键指纹，固定选择原无序 ID `0,1,7`（含此前诊断较弱的一套；这是便利／压力子集，不是总体无序的代表性估计）。两臂都使用四个真实副本，分别运行独立种子的随机初态组和全 `+1` 有序初态组。全同向在自旋玻璃中并非低能／基态，接口名 `cold` 不能解释为低能夹逼。每臂每组固定预热 8192 个完整格点访问轮，再间隔 16 轮保存 512 个样本；总计 20,384,317,440 次局域格点访问，Houdayer 簇工作另计。全部实验仅占一条 nice 10 CPU 线程，GPU 用量为零；一核时和 1 GiB 目录为阶段间软预算，不是中途强杀时限。预算不足时保留结果并等待用户，不自动扩展、降规模、重启或续跑。

控制臂使用懒惰局域 Metropolis 加平行回火，新臂额外在每温度随机配对四个副本，并同时翻转完整的非零键连通 `q=-1` 簇。该更新保持选中副本对的逐点重叠及联合能量，但分别改变双方的能量，必须更新两份能量后才能做正确的温度交换；它本身不遍历全部状态，局域更新不可省略。四副本的其他交叉重叠可以变化。六个副本对不是六条独立轨迹，诊断先按每个时刻平均 `q²`，再估自相关、ESS、分段误差及初态差。簇更新后，温度往返标签不再对应一份完整微观构型的祖先，只作标签输运诊断，不作热化证书。输出包含簇大小、空操作／全格簇、能量核验、包含预热的轨迹和单位全程耗时 ESS。平稳性和初态一致性应先于加速解释；仍不自动认证平衡。

新增独立模块 `recurrent_rg.data.spin_glass_houdayer` 不修改原 `spin_glass.py` 或旧数据协议。试验在新根内冻结源码，每个采样 case 单独记录种子、键 SHA、原始数据 SHA、时长及资源回执，公共报告只含聚合统计和中文图，不包含模型或原始构型。`--execution-smoke` 是小规模执行验证，不能作为物理结果。

## Houdayer 新数据直接训练（本次明确授权）

用户随后明确要求“不用管内存和时间限制，直接训练”。因此独立 PT 对照试验没有正式启动；前置 `smoke_v1` 因编译进程约 543 MiB 超过当时自设的 512 MiB 门槛而停止，保留为执行记录，不是物理结论。新增独立入口 `scripts.run_spin_glass2d_houdayer` 使用新数据直接从头学习，不继承这些行政时间／内存上限，也不传训练时间截止参数。共享 GPU 空闲、主机内存／负载／I/O 检查仍保留，固定 `cuda:2`，等待资源不干预他人。该授权只适用于本次实验，不修改以后实验的默认资源政策。

新正式物理数据保留原 9 套 `J` 的指纹与 20 个温度，四个真实副本均从随机初态启动，以新热采样种子空间执行“懒惰局域 Metropolis＋随机副本配对 Houdayer＋平行回火”。每副本每温度固定预热 8192 轮、间隔 16 轮保存 512 个构型，共 15,288,238,080 次局域格点访问，簇遍历另计。数据格式兼容原严格加载器，但明确记录新采样器及副本耦合关系。专用 `scripts.prepare_spin_glass_houdayer_qcr` 仅将预定重叠对 `0/1` 转为每 `(J,T)` 一个系综，其他两个副本仅辅助混合；保持 120 TRAIN／60 TEST 系综，缓存不含 `J/T` 标签。

新配置 `configs/spin_glass2d_houdayer_overlap_g1_seed91.json` 的模型、loss、优化器、seed 和训练／评价批量与原二维配置相同：`d_g=1`、`36→12→4`、默认随机可训练 `3×3` C、等权目标尺度闭合、fresh Adam 0.001、6000 次更新、每批 64 构型。512 个保存时刻均进入训练池和经验 MI 支撑，但正式报告沿用每系综前 64 个预热后保存构型，避免把“保存 512”误称“评价全部 512”。无额外 future/response/温度监督 loss。由于采样核、副本数、预热和保存量同时变化，本轮不是严格的 Houdayer 单因素消融。

四副本为耦合马尔可夫轨迹，没有额外独立随机／有序组对照，仍不认证热化。有限链 ESS、簇统计、能量一致性和往返均如实保存；新增流场的绝对 `g` 坐标不与历史坐标直接混比，也不通过交点自动认证临界指数。正式开始后冻结源码，不自动修复、重启或覆盖旧根。
